# 『焚書の夜』設計書

> 仮題。最下層で世界の原文に言葉を書き込む、タイピング詠唱RPG。

---

## 0. この文書の位置づけ

実装前の確定仕様書。ここに書かれた数値・アルゴリズムは実装の正とする。
変更する場合は必ずこの文書を先に更新してから実装する。

特に **第3章のハッシュ関数は、一度確定したら絶対に変更してはならない**（理由は 3.5）。

## 1. 作品概要

| 項目 | 内容 |
|---|---|
| ジャンル | 2D タイピング詠唱RPG |
| プレイ時間 | 約60分（初回） |
| 周回 | あり。呪文帳・断章・エンディングはセーブを跨いで蓄積 |
| 舞台 | 王立書庫の内部のみ。屋外マップは存在しない |
| プラットフォーム | Web（PC・キーボード必須） |
| 公開 | Cloudflare Pages（無料枠） |

### コンセプト

**プレイヤーが覚えた言葉が、そのままキャラクターの力になる。**

通常のRPGでは主人公が魔法を覚えてもプレイヤーは何も覚えない。本作では
呪文の習得＝キーボードの前の人間が文字列を記憶することであり、両者は完全に一致する。
このため「習得しました」というシステムメッセージは**一切表示しない**。
知ってしまえば、その瞬間から使える。

## 2. 世界観と物語

### 2.1 前提設定（本編で説明しない）

- 魔法とは言葉である。正しい語を口にすれば現象が起きる
- ゆえに国家は言葉を独占管理している。平民が呪文を唱えることは重罪
- 王立書庫は、その管理の中枢

これらは導入で説明しない。プレイヤーは「打ち込む」という行為を通じて理解する。
**冒頭に世界設定の語りを置くことを禁止する。**

### 2.2 主人公

書庫の**見習い**。仕事は本を運び、埃を払い、背表紙の題名を目録に書き写すこと。
**読むことは許されていない。** ——でも、こっそり読んでいた。

- 名前はプレイヤーが起動直後にアルファベットで入力する（4〜8文字）
- ゲーム開始時点で呪文を1つ知っている。ミラが教えたから
- 最下層（禁書庫）への立ち入りは、見習いには禁じられている

### 2.3 ミラ `MIRA`

1年先輩の見習い。禁を破って最初に本を読んだ人物であり、主人公に最初の呪文を教えた。

> 「ねえ、これ読める？」
> ミラは埃だらけの指で、閉じた本の背をなぞった。
> 「わたしね、`ROZHA` って打ったら、指先が熱くなったの」

**第1章の15分間、特別なイベントは何も起こさない。ただ、いる。**
棚の陰で勝手に本を読んでいる。目録に落書きをしている。話しかけるたびに違うことを言う。

**第2章冒頭、炎が上がった直後の混乱で失われる。**
死体も、別れの台詞も、感動的なシーンもない。気づいたら、いない。
以降40分、主人公は誰とも話さず一人で降りていく。

#### 設計制約（最重要）

ラストでプレイヤーが `MIRA` と**打てなければ**、この物語は成立しない。したがって：

- 名前は4文字のアルファベット固定
- 第1章の間、画面に**最低20回**は `MIRA` の文字列を露出させる
  （呼びかけ、台詞中、目録の署名、扉の張り紙、落書き）
- 会話ウィンドウ内では常に等幅・アルファベット表記で出す

### 2.4 焚書を指揮する者（ラスボス）

**禁書に名前を消された誰かを覚えている、世界で唯一の人間。**

消された者は「初めからいなかったこと」になる。だから世界の誰も覚えていない。
記録も残らない。なのにこの人物の中にだけ、穴が残っている。
名前も顔も思い出せない。ただ「誰かがいた」という感触だけが何十年も消えない。

書庫を焼くのは、他の誰にも禁書を使わせないため。**自分だけが書き換えたい。**

> 「名前を、教えてくれないか」
> 「わたしは、その名前を、知らないんだ」

プレイヤーは `MIRA` を覚えている。まだ消されていないから。
この対比だけでラスボス戦の意味が立つ。説明台詞は不要。

### 2.5 禁書 ＝ この世界の原文

そこに書かれていることが、現実になっている。

- 名前を書き加えれば、その者は存在したことになる
- 名前を消せば、その者は初めからいなかったことになる

**任意ルール（採用は実装時に判断）：** 原文は有限であり、一行書き加えるなら一行消えなければならない。
採用すると「ミラを取り戻す代償に誰かが消える」となり、空欄エンディングが劇的に重くなる。
不採用でも物語は成立する。

### 2.6 隠し要素：この世界を書いた者

禁書に原文があるなら、それを書いた者がいる。**本編では一切触れない。**
最下層のどこかに、読めない一語が落書きとして落ちているだけ。
それを禁書に書き込んだプレイヤーだけが到達する。

### 2.7 章構成

| 章 | 内容 | 尺 | Lv | MP |
|---|---|---|---|---|
| 第1章 静かな書庫 | 平時。ミラとの日常、最初の呪文、書庫の害獣との軽い戦闘 | 15分 | 1→3 | 開始時全回復 |
| 第2章 焚書 | **同じマップの炎上版**。ミラの喪失、逃走と探索、兵士との遭遇 | 20分 | 4→7 | 開始時全回復 |
| 第3章 禁書庫 | 最下層。焚書を指揮する者、そして禁書 | 20分 | 8→12 | 開始時全回復 |
| 終章 夜明け | 禁書への書き込み → エンディング | 5分 | — | — |

**第1章が退屈な日常であるほど、第2章が効く。** ここを削ってはいけない。

### 2.8 マップ再利用の原則

第1章と第2章は**同一のマップデータ**を使う。
第2章では以下のみ変更する：

- パレットを赤系にシフト（描画時のカラーフィルタ、アセット複製は不要）
- 炎パーティクルレイヤーを重ねる
- 一部の通路を瓦礫で封鎖（通行可否テーブルの差分のみ持つ）
- NPCの配置を消す

実装コストはほぼゼロで、体験の破壊力は最大。**本作で最も費用対効果の高い演出。**

## 3. 詠唱システム（本作の心臓部）

### 3.1 基本ルール

- 戦闘中、プレイヤーは**1ターンに1回だけ**文字列を入力してEnterを押す
- 入力は半角英数字のみ（IME不要。日本語入力は一切要求しない）
- **時間制限なし。** 速さは一切問わない
- 入力欄はゲーム内で描画する自前UI（DOMの`<input>`は使わず、keydownを直接拾う）

### 3.2 入力補完（全能感の担保）

**呪文帳に登録済みの呪文は、入力中に前方一致でサジェストされる。**

```
入力: FAL
候補: FALGRIM  (炎・単体・大  MP12)
```

Tab または ↓ で候補を確定できる。これにより：

- 既知呪文は打ち間違えない → ストレスなく撃てる ＝ **全能感**
- 補完が効かない文字列を敢えて打つときだけ、真っ暗な賭けになる

この対比が本作の手触りを決める。

### 3.3 ハッシュ関数

FNV-1a 32bit。ライブラリ不要。

```ts
/** 呪文文字列を32bit整数へ変換する（FNV-1a） */
export function spellHash(input: string): number {
  // 正規化：前後空白除去 → 大文字化 → A-Z0-9 以外を除去
  const s = input.trim().toUpperCase().replace(/[^A-Z0-9]/g, "");
  let h = 0x811c9dc5;
  for (let i = 0; i < s.length; i++) {
    h ^= s.charCodeAt(i);
    h = Math.imul(h, 0x01000193) >>> 0; // 32bit積を維持
  }
  return h >>> 0;
}
```

### 3.4 呪文の決定：余りで帯、商で個体

```ts
const h = spellHash(input);
const r = h % 10000;            // 余り：レア度帯
const q = Math.floor(h / 10000); // 商：帯内の個体
```

| `r` の範囲 | 帯 | 出現率 | 種類数 |
|---|---|---|---|
| 0 〜 999 | 不発 | 10% | — |
| 1000 〜 4699 | コモン | 37% | 20 |
| 4700 〜 8199 | アンコモン | 35% | 20 |
| 8200 〜 9699 | レア | 15% | 12 |
| 9700 〜 9999 | **神話** | 3% | 5 |

帯が決まったら `q % 帯の種類数` で個体を決める。**呪文総数 57種。**

### 3.4.1 この配分の意図

**ミラがくれる最初の呪文はアンコモン帯に置く。** これが乱打の基準線になる。

| 乱打の結果 | 確率 |
|---|---|
| 最初の呪文より弱い（コモン・不発） | 47% |
| ほぼ同等（アンコモン） | 35% |
| **強い（レア・神話）** | **18%** |

期待値では既知呪文を撃つほうがまだ得だが、その差はかなり小さい。
**「打ってみるか」と思える確率**であることを最優先した配分である。
不発率を高くすると賭けが割に合わなくなり、本作の核である「掘り当てる楽しさ」が死ぬ。

**この気前のよさの代償として、乱打抑止はMP経済にほぼ一本化されている（3.7）。**
5.1 の入手数を増やすと、乱打が最適戦略に転落する。

神話3%なら、1周で20回賭けたプレイヤーの約46%が一度は引く。
半分が体験し、半分が2周目の動機として残る。

### 3.4.2 【重要】コモンは「弱い呪文」ではない

出現の47%がコモンである以上、ここが単なるハズレだと**約半分の賭けがガッカリになる**。
不発率を下げた意味がなくなる。

コモンは**弱いのではなく、安くて状況特化**にする。

- MP 3〜6。アンコモン1回ぶんで3回撃てる
- 弱点を突けば倍率でアンコモンを上回る
- 状態異常・防御低下・行動阻害など、火力以外の役割を持つものを混ぜる

「コモンが出た」を損ではなく**別の道具が手に入った**にすること。

不発時の表示：

```
　言葉は、意味をなさなかった。
　（MP 3 を失った）
```

神話級を引いたときは専用演出を入れる（画面暗転・文字が浮かび上がる・SE）。

### 3.5 【厳守】ハッシュ関数と帯境界は凍結する

**凍結対象はハッシュ関数だけではない。3.4 の帯境界値（`r < 1000` 等）も同じく凍結する。**
ハッシュ関数を守っても境界が動けば、`FALGRIM` がレアからアンコモンへ滑り落ちる。
配分（10 / 47 / 27 / 13 / 3）を変更できるのは Phase 2 の逆引きを実行する前まで。


**巻物に載せる呪文名は「逆引き」で決定する。**
`FALGRIM` に炎の効果を割り当てることはできない。ハッシュが決めてしまうため。

したがって手順は以下になる：

1. ハッシュ関数と帯テーブルを確定する
2. 発音しやすい文字列を数万個自動生成する
3. 全部ハッシュして、狙った呪文IDに当たるものを集める
4. その中から響きのいいものを人間が選び、巻物に載せる

**この時点でハッシュ関数を1文字でも変更すると、全呪文名が別物になり、シナリオ・巻物・
会話テキストが全部壊れる。** Phase 1 で確定させ、以後凍結する。

副産物として、同じ効果を持つ文字列が複数存在する。これは設定で回収する：

> 真の名は一つではない。言葉は違えど、同じ扉を叩く。

### 3.6 呪文の効果パラメータ

```ts
type Spell = {
  id: number;
  tier: "COMMON" | "UNCOMMON" | "RARE" | "MYTH";
  name: string;        // 表示名（日本語の異名）例：「灯火」
  canonical?: string;  // 巻物に載る代表文字列。逆引きで決定
  element: "FIRE" | "ICE" | "BOLT" | "NAME" | "HEAL" | "NONE";
  target: "SINGLE" | "ALL" | "SELF";
  power: number;       // 威力またはHP回復量の基礎値
  mp: number;
  fx: string;          // 演出ID（使い回し可）
  flavor: string;      // 呪文帳に載る一文
};
```

#### MPコストの目安

呪文は威力ではなく**役割**で階層化する。MPの階段がそのまま役割の階段になる。

| 役割 | 帯 | MP | 使う場面 |
|---|---|---|---|
| **削り** | コモン | **2 〜 5** | 弱い敵を、命（MP）を削らずに片づける |
| **常用** | アンコモン | 7 〜 11 | ほとんどの戦闘。**最初の呪文がここ＝基準線** |
| **決め手** | レア | 14 〜 20 | ボス、ピンチ |
| **一度きり** | 神話 | 40 〜 60 | 終盤に一回 |

不発は 3 MP 固定。

### 3.6.1 巻物コモンは MP2 にする

**巻物でコモンが見つかっても使われない**、という問題への対処。

威力12/MP4 のコモンと 威力24/MP8 のアンコモンは、MPあたりの効率が同じ 3.0 で、
ターンあたりの火力だけが半分になる。つまり厳密な下位互換であり、誰も使わない。

そこで**巻物コモンは威力10/MP2 とする**。MP効率 5.0 でアンコモンを大きく上回り、
弱点を突けば 20 ダメージが MP2 で出る。**MPが実質のライフバーである以上、
「命をほとんど削らずに撃てる」ことは終盤まで価値を失わない。**

これにより、入手経路で性格が分かれる。

- **巻物** … いつでも撃てる実用品。安く、属性を揃える鍵
- **発掘** … 一撃の博打

国家が管理していた実用魔法と、失われた大魔法。設定とも一致する。

### 3.6.2 MPを回復する呪文は作らない

MPが実質のライフバーである以上、MPを生む呪文があると経済が丸ごと崩れる。
HPを対価にMPを得る呪文も、HP回復が呪文（＝MP）で行える以上、無限ループになる。
**回復手段はインク壺と魔力の雫だけ（5.1）。**

最上位の神話（MP 60）は第2章終了時点の最大MP 52 でもまだ届かない。
**「知っている、だが届かない」を終盤まで持続させる。**

序盤に神話級を引き当てた場合の演出（**本作の目玉のひとつ**）：

```
　——VORNAX。

　舌がその形を覚えた瞬間、指先から力が抜けた。
　知っている。だが、まだ届かない。

　［呪文帳に記録：VORNAX ／ 未詠唱］
```

### 3.7 乱打対策（3枚重ね）

不発率を10%に下げたため、**抑止の主力はMP経済に移った**。以下の3枚で支える。

1. **1ターン1詠唱＋期待値** — 乱打の57%は既知呪文より弱い。手番を捨てることになる
2. **MPの錠前（主力）** — 神話級は最大MPに迫るコスト。引いても大半の場面で撃てない
3. **入力補完** — 既知呪文は快適に撃てる。未知の入力だけがリスクを負う

乱打が自己懲罰になる経路は「手番を失う → 余計に殴られる → 回復にMPを使う」である。
つまり**MP経済が緩むと抑止が丸ごと消える。** 5章の入手数を安易に増やしてはならない。

## 4. 戦闘

### 4.1 基本

- **主人公ソロ。パーティメンバーは存在しない**
  （実装量の削減と、詠唱の主役性の担保。孤独が仕様）
- ターン制。プレイヤー行動 → 敵行動 の繰り返し
- プレイヤーの行動は3択：**詠唱 / 道具 / 逃げる**

### 4.2 エンカウント

**シンボルエンカウント。ランダムエンカウントは実装しない。**
マップ上に敵シンボルが見えており、接触で戦闘。全戦闘が手配置。
避けられる戦闘があってよい。

全編の戦闘数：**15〜25回**（うちボス3体）。

### 4.3 敵：3つの系統

**「ただの物が敵になる」構成は避ける。** こぼれた墨や読まれなかった詩をそのまま敵にすると、
32pxのドット絵で何と戦っているのか読み取れず、物語としても違和感が出る。

敵を3系統に分け、**章が進むほど異常になる**構成にする。

| 章 | 系統 | 敵 | 特徴 |
|---|---|---|---|
| 1 | **書庫の生き物** | 紙喰い虫 | 拳大の虫。チュートリアル用。`INSECT` |
| 1 | | 墨のスライム | 硬いが雷に弱い粘体 |
| 2 | **召喚された魔物** | 煤蝙蝠の群れ | 多数。全体攻撃が有効。目つぶし |
| 2 | | 焔鬼 | 火を吐く小鬼。炎耐性・氷弱点 |
| 2 | **人間** | 焚書隊の兵士 | **希少に配置し、一戦を重くする** |
| 3 | **言葉が変じたもの** | 抹消された名前の者 | 炎氷雷が無効。`NAME` でのみ通る。忘却 |
| 3 | | 灰の中の声 | 中ボス |
| 3 | **召喚された魔物** | 業魔 | 大鬼。指揮者が連れてきた。`NAME` 弱点 |

#### なぜ書庫に魔物がいるのか

**焚書隊が、焼くために召喚してきたから。** これで設定の穴が塞がる。

そして重要なのは、**第1章に魔物を出さないこと**。平時の書庫にいるのは害虫だけで、
魔物は侵入者と一緒に降りてくる。第1章の日常が守られ、第2章の異常さが際立つ。

### 4.3.1 「忘却」は呪文帳を封じる

抹消された名前の者の技。プレイヤーへの `SILENCE` は、**行動を封じない。**
本作でプレイヤーができることは詠唱だけなので、それを止めると手番を奪うだけの
理不尽な技になる。

代わりに、数ターンのあいだ **呪文帳を開けなくし、入力補完も無効化する。**

> 呪文帳を開いた。
> ……頁の文字が、読めない。

> 覚えていたはずの綴りが、思い出せない。

打てないのではない。**思い出せない**。プレイヤーは自分の頭に残っている綴りだけで
`ROZHA` を打ち切るか、当てずっぽうに賭けるしかない。
**敵が攻撃してくるのは能力ではなく記憶**であり、このゲームでしか成立しない攻撃になる。

消された者が、こちらの記憶を消しにくる——という筋も通る。

### 4.4 ダメージ計算

```ts
// 攻撃呪文
damage = Math.floor(spell.power * (1 + level * 0.15) * elementMultiplier) - enemy.def;
// 弱点 x2.0 / 耐性 x0.5 / 無効 x0
damage = Math.max(1, damage);

// 回復呪文
heal = Math.floor(spell.power * (1 + level * 0.15));
```

### 4.5 成長

レベルは**物語進行で自動的に上がる**。経験値稼ぎは存在しない。
1時間作品にレベリングの余地はなく、レベルは設計者が完全に管理する。

| Lv | HP | MP | 到達タイミング |
|---|---|---|---|
| 1 | 30 | 30 | 開始 |
| 3 | 45 | 38 | 第1章終了 |
| 7 | 80 | 52 | 第2章終了 |
| 12 | 130 | 70 | 第3章終盤 |

最初の呪文がアンコモン（MP 7〜11）なので、初期MP 30 で3〜4回撃てる。
最大MP 70 に対し神話級は 40〜60。**終盤に一度だけ解き放てる。**

## 5. MP経済

| ルール | 内容 |
|---|---|
| 自然回復 | **なし**。歩いても戦闘が終わっても戻らない |
| HP回復 | 呪文（`HEAL` 属性）で行う |
| **帰結** | **実質のライフバーはMP。言葉を使うほど命が減る** |
| 宿屋 | 存在しない（そもそも町がない） |
| 章の切れ目 | MP・HP 全回復。章内（戦闘5〜8回）が一つの勝負単位 |

「実質のライフバーがMP」という構造は、そのままテーマである。
**全能感を味わうほど、終わりが近づく。**

### 5.1 回復アイテム：量ではなく形で制御する

不発率を下げた以上、乱打抑止はMP経済が一手に担う（3.7）。
したがって回復手段は**小口を大量に配り、上限は上げない**。

| アイテム | 回復量 | 入手数 | 性格 |
|---|---|---|---|
| **インク壺** | MP+10 | 第1章 8 / 第2章 6 / **第3章 4** ＝計18 | 書庫のそこら中にある。気軽に賭けられる |
| **魔力の雫** | MP+30 | 全編 6個 | 希少。ここぞの一発のために取っておく |

判断の焦点が「MPがあるか」から**「大物を撃つぶんを残せるか」**に移る。

#### 設定との一致

**MPの正体はインクである。** 言葉を書くにはインクが要る。
書庫が舞台なので、そこら中に転がっている理由は説明不要。

そして**章が進むほど焼けて減っていく（8 → 6 → 4）。**
難易度カーブが物語の進行とそのまま一致する。

## 6. エンディングシステム（禁書）

### 6.1 演出

最下層。開かれた禁書。ページは白紙で、羽根ペンが置かれている。
そして画面に、**戦闘中とまったく同じ入力欄**が出る。

ただし今回はヒントも候補も制限時間もない。
**ゲームは、プレイヤーが何かを打ち込むまで永遠に待つ。**

```
　禁書のページに、羽根ペンを走らせる。

　［　＿＿＿＿　　＿＿＿＿　　＿＿＿＿　］
```

**最大3語**まで書き込める。1語でも2語でもよい。

### 6.2 判定ロジック

```ts
/** 3語を順序非依存の1キーへ正規化する */
export function endingKey(words: string[]): string {
  const uniq = [...new Set(
    words.map(w => w.trim().toUpperCase().replace(/[^A-Z0-9]/g, "")).filter(Boolean)
  )].sort();
  return uniq.join("|");   // 例: "FALGRIM|MIRA|VORNAX"
}
```

判定順：

1. **空欄のままEnter** → 専用エンディング「本を閉じる」
2. `endingKey` が **AUTHORED テーブル**（20〜30通り）にヒット → 専用エンディング
3. それ以外 → `spellHash(endingKey) % FRAGMENTS.length` で**断章プール**（40本）から1本

順序非依存にするのは、プレイヤーに語順を強いないため。
AUTHORED はハッシュ値ではなく**キー文字列そのもの**を辞書キーにする（可読・デバッグ容易）。

### 6.3 専用エンディング（手書き・20〜30通り）

物語中で出会った語の組み合わせに対して用意する。例：

| キー | 内容 |
|---|---|
| （空欄） | **本を閉じる。** 何も書き換えない。最も重い結末 |
| `MIRA` | ミラが生きている世界になる |
| `（主人公名）` | 見習いは初めから存在せず、書庫は燃えなかったことになる |
| `（指揮官名）` | 焚書を指揮した者を消す。……本当にそれでいいのか |
| `MIRA｜（主人公名）` | 二人とも。原文有限ルールを採用した場合、代償が発生する |
| `（神話級呪文）` | 隠し結末 |
| `（読めない一語）` | この世界を書いた者へ到達する |

### 6.4 断章プール（40本 × 3〜5行）

エンディングではなく、**書き換わった世界の断片**。

> 　書庫は燃えなかった。
> 　代わりに、その街には図書館が存在したことがない。
> 　誰も、そのことを不思議に思わない。

- テキストは全アセット中もっとも安い。40本でもドット絵1キャラぶんの工数
- 背景は「夜明けの書庫」1枚を使い回す
- 収集要素として記録し、タイトル画面から閲覧可能にする

### 6.5 「何も書かない」について

**これだけは絶対に手書きで作り込む。**

世界を書き換える力を手に入れて、書き換えないことを選ぶ。
60分間ずっと「言葉を打て」と要求してきたゲームが、最後に打たないことを許す。

プレイヤーはそれが選択肢だと気づかないかもしれない。
入力欄を前に何分も悩んで、そっとEnterを押す。**その体験は設計できない。**

## 7. 技術仕様

### 7.1 スタック

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | TypeScript | 型でデータ構造を固定できる |
| ビルド | Vite | 設定ゼロで起動、HMR |
| 描画 | Canvas 2D（フレームワークなし） | 依存を増やさない。本作は演出が軽い |
| UI | 自前描画 | 入力欄含め全てCanvas内に描く |
| 保存 | localStorage | 呪文帳・断章・エンディング収集 |
| 公開 | Cloudflare Pages | 無料・従量課金なし |

**ゲームエンジン（Phaser等）は使わない。** 本作に必要なのはタイルマップ描画・
テキスト描画・キー入力だけであり、いずれも数百行で書ける。依存が増えるほど
バイブコーディングでAIが把握しづらくなる。

### 7.2 解像度

- 内部解像度 **480 × 270**（テキスト量が多いためやや広め）
- ウィンドウサイズに合わせて**整数倍**でスケール（×4 で 1920×1080 ぴったり）
- `ctx.imageSmoothingEnabled = false` でドットを保つ
- タイルサイズ 16px

### 7.3 フォント

日本語ドットフォントが必須。**PixelMplus12**（12px、フリー）を第一候補とする。
ライセンス条件は導入時に必ず確認すること。

12px × 480px幅 → 1行あたり全角約36文字。会話ウィンドウは3行。

### 7.4 マップ形式：アスキーアート

**Tiled等のGUIエディタは使わない。** マップはテキストファイルで持つ。

```
# maps/ch1_reading_room.map
#############################
#...........................#
#..BBB....T....BBB..........#
#..BBB.........BBB....@MIRA.#
#...........................#
#####.................#######
```

| 記号 | 意味 |
|---|---|
| `.` | 床（通行可） |
| `#` | 壁 |
| `B` | 本棚 |
| `T` | 机 |
| `@` | イベント/NPC配置点（直後の識別子で紐づけ） |
| `E` | 敵シンボル配置点 |
| `>` `<` | 階段 |

**この形式はAIがそのまま読み書きできる。** バイブコーディングとの相性が最も良い。

### 7.5 画面ステート

```
TITLE → NAME_INPUT → FIELD ⇄ BATTLE
                       ↓  ⇅ MENU（呪文帳・道具）
                    GRIMOIRE（禁書）→ ENDING → TITLE
```

## 8. アセット方針

### 8.1 ハイブリッド運用（確定）

| 用途 | 調達 | 理由 |
|---|---|---|
| **立ち絵・顔グラ** | **AI生成** | 「ちゃんとしたキャラ」を見せたいのはここ。6〜8人ぶん |
| マップ上キャラ（16px） | フリー素材 | AIは4方向×3フレームの一貫性を出せない |
| マップチップ | フリー素材 | 書庫内装1セットのみ。統一感が最優先 |
| 敵グラフィック | AI生成 | 「言葉の怪物」は非実在の抽象形でよく、一貫性の要求が低い |
| エフェクト | 自前（矩形・円・パーティクル） | Canvas描画で十分 |

**マップ上のキャラとマップチップは、必ず同一の配布元で揃える。**
ここが混ざると画面全体が寄せ集めに見え、シナリオがどれだけ良くても安っぽくなる。

### 8.2 必要な立ち絵

1. 主人公（見習い）
2. ミラ
3. 焚書を指揮する者
4. 司書長
5. 焚書隊の兵士
6. 灰の中の声（中ボス）
7〜8. 予備

### 8.3 作り込みの配分（スコープ管理）

呪文57種を全部作り込むと1時間作品の工数を超える。

| 区分 | 数 | 作り込み |
|---|---|---|
| 巻物呪文（物語に絡む） | 12〜15 | 専用エフェクト・フレーバー・逆引きで名前を厳選 |
| 発掘専用呪文 | 30前後 | 既存呪文の数値・属性違い。エフェクト使い回し |
| 不発 | — | 実装ゼロ |

**「57種の呪文が存在する世界」を、実質15個ぶんの作り込みで成立させる。**
