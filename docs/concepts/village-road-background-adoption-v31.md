## 2. 建築と構図

左右の家は、急勾配48〜55度の正面切妻、暗い垂木、木板と古いスレートの補修葺き、実用的な石煙突を持つ。白い漆喰、木の柱、青緑の窓、中央の共同井戸、畑、遠景の丘、水平な土道を固定景観にする。豪邸や城下町ではなく、王国から遠い、困窮していても手入れの続く西・中欧系農村として読む。

道上端はゲーム座標162、人物足元は176。中央の歩行帯と下部の会話UI領域を平らに保つ。

## 3. 画像とコードの分担

PNGへ固定したものは、家、屋根、煙突、窓、井戸、柵、畑、丘、空、朝の基礎光、静的な路面である。

次は物語状態なので `drawVillageRoadStoryState` と各Sceneのコード層に残した。

- 行商人到着後の荷車と積荷
- 火災の日付判明後の記録紙
- 主人公、セナ、行商人などの人物
- 十年前の暗い色幕と村の灯り
- 終幕の夕方の青紫・古金の色幕
- 会話、目的、操作UI

`isVillageRoadBackgroundReady` が読込完了と960×540を確認できない場合は従来のコード村道へ戻る。物語進行や状態小物は画像の成否に依存しない。

## 4. 接続

`series2Assets.ts` の正式目録から起動時に読み、同じ画像を次へ渡す。

- `OpeningScene`：十年前の遠い村
- `SideViewScene`：第一章の到着前／行商人到着／日付判明
- `Series2EndingScene`：二人が歩く夕暮れの村道
- DEV「背景　4地域比較」：コード版との比較と三状態

DEV比較も資料PNGのURLを廃止し、正式Manifestの画像と本番の `renderVillageRoad` を使う。通常進行へ比較操作は含めない。

## 5. 実画面確認

ローカルブラウザで、正式Manifestを読む経路を確認した。

- DEV村道比較の到着前／行商人到着／日付判明で、固定背景を変えず荷車と記録紙だけが増える
- 正式な成人主人公が足元176へ接地し、会話UIが静かな下部路面へ収まる
- 単一ED第2頁で、夕方の青紫と古金を重ねても左右の切妻と煙突を識別できる
- 主人公とセナが2.9秒で移動後、正式村道上の中立足へ停止する
- DEV表示以外に資料PNGのURLを使わず、正式Manifestから配布画像を読む

## 6. 自動検証

- `npm run build`：TypeScriptと本番build成功
- `npm run verify:assets`：正式15エントリの命名、ID、寸法、透過、ハッシュ、欠落・余分なし
- `npm run verify:village-road-trial`：v30原本からの決定的変換と正式PNGの同一バイト列
- `npm run verify:village-road-story`：導入・第一章・終幕への注入、動的状態、フォールバック、DEV共通経路
- `npm run verify:character-story-integration`：終幕の人物移動と停止時刻
- `npm run verify:bundle`：19ファイル。正式村道を含み、原本・比較資料・DEVパスなし

村道は正式採用で閉じる。次は村道の屋根と石・木の材質を基準に、村門を1画面だけ少数試作する。門そのもの、柵、森との境界を固定し、警告布、狩人装備、通行止めの横木、開門状態は動的層に残す。
