# 台本の書き方

会話文はコードを触らずに直せます。**このファイルの規則だけ守れば、あとは自由です。**
直したら最後に `npm run lint:script` を走らせてください（枠からはみ出す行を機械が見ます）。

---

## 1. どのファイルを直すか

| ファイル | 中身 |
|---|---|
| `data/dialogue/ch1.json` | 第1章。ミラ、司書長、巡回当番表、目録、机の落書き |
| `data/dialogue/ch2.json` | 第2章。**変わったものだけ**書く。無いものは第1章の文がそのまま出る |
| `data/dialogue/ch3.json` | 第3章。灰の中の声、HALVEN、禁書庫の落書きと台 |
| `data/dialogue/notices.json` | 本棚・写字机・燭台・階段を「しらべる」ときの一行 |

すべて JSON です。**日本語の中の `"` と `\` だけ気をつけてください**（そのままでは書けません）。

## 2. 話者ひとりぶんの形

```json
"mira": {
  "name": "ミラ",
  "color": "#c8845a",
  "portrait": "mira",
  "chapters": [1],
  "found": {
    "ch1_reading": ["ミラは閲覧室の隅で、返却された本を抱えていた。"]
  },
  "grants": [{ "talk": 3, "id": 3, "word": "PROSO" }],
  "talks": [
    ["「ねえ、これ読める？」", "ミラは埃だらけの指で、本の背をなぞった。"],
    ["「わたしね、ROZHA って打ったら、指先が熱くなったの」"]
  ]
}
```

| 項目 | 意味 |
|---|---|
| `name` | 窓の左上に出る名札。空にすると名札が出ない（地の文だけの場面） |
| `portrait` | 立ち絵。`public/assets/portraits/<これ>.png` |
| `chapters` | この人物が現れる章。書かなければ全章 |
| `found` | **その部屋で見つけたときの一行。** 会話の頭に必ず入る |
| `grants` | その会話で呪文帳に加わる言葉 |
| `talks` | 会話の本体。**話しかけるたびに次へ進む** |

## 3. 守ってほしい規則

### 3.1 喋っている行は「」で包む

**立ち絵のある人物の窓では、鉤括弧の無い行は「地の文」の色（灰色）で出ます。**

```json
["「ねえ、これ読める？」", "ミラは埃だらけの指で、本の背をなぞった。"]
```

上の行が本人の声（明るい色）、下の行が描写（灰色）になります。

**続きものの台詞でも、1行ずつ閉じてください。** 行ごとに色を決めているためです。

```json
["「なんて話しかけたらいいか、」", "「分かんないんだと思う」"]   ← ✕ 中途半端
["「なんて話しかけたらいいか、分かんないんだと思う」"]           ← ○
```

張り紙・目録など**立ち絵の無いもの**は、全部が読み上げなので鉤括弧は不要です。

### 3.2 1行の長さ

| | 上限（全角） |
|---|---|
| 立ち絵のある人物 | **29文字** |
| 張り紙・目録など | 35文字 |
| 家具の一行（notices） | 35文字 |

はみ出すと**ゲーム中で黙って切れます。** 目では気づけないので `npm run lint:script` で見てください。

### 3.3 3行で1ページ

`talks` の1つは3行ずつ送られます。4行だと最後のページが1行になり、間延びします。
**3の倍数が気持ちよく収まります**（守らなくても動きます）。

### 3.4 大文字は自動で色が変わる

`ROZHA` `MIRA` `PROSO` `HALVEN` のように**大文字が3つ以上続く部分は、自動で目立つ色**になります。
印を付ける必要はありません。逆に、**目立たせたくない大文字は書かないでください。**

### 3.5 最後の会話は繰り返される

`talks` の最後まで行くと、以後はその最後の1つが何度でも出ます。
**「立ち去りかけの一言」を最後に置くと自然です。**

ミラだけは例外で、**最後の会話を閉じた瞬間に第1章が終わります。**
彼女の `talks` の最後は「別れの挨拶」でなければいけません。

### 3.6 `found` は必ず読まれる

会話16回のすべてで頭に1行入ります。**1つしか書かないと16回同じ文を読ませることになります。**
部屋ごとに3つ書いてあるので、増やすか、書き換えるかしてください。

**部屋の中の実際の立ち位置と食い違わないように。**
「階段に腰かけていた」と書くなら、`data/maps/ch1_stairs.room` の `a` が階段の隣にある必要があります。

## 4. 直したら

```bash
npm run lint:script
```

枠からはみ出した行、鉤括弧の閉じ忘れ、存在しない立ち絵の指定を報告します。

```bash
npm run count:mira
```

`MIRA` がプレイヤーの目に何回入るかを数えます。
**この数字は下限（12回）を割らないかを見るだけのものです。目標にしないでください。**
一度これを最大化しにいって、ミラが「署名を書く装置」になりました（設計書 2.3）。


## 倒したときに呪文を渡す（`reward`）

`battleAfter` を持つ相手には `reward` を書ける。**勝ったときだけ**渡る。
逃げても負けても渡らない。

```json
"ashvoice": {
  "battleAfter": "ashvoice",
  "reward": {
    "id": 52,
    "word": "DIZO",
    "lines": ["積み上がっていた本が、崩れて散らばった。", "..."]
  }
}
```

- `lines` は**呪文の受け渡し通知ではなく、倒した相手がどうなったかの描写**。
  すでにその呪文を自力で掘り当てていた人にも、この文は出る。
  「呪文帳に書き加えられた」の一行だけが、初めてのときに足される。
- `word` は必ずその `id` に当たる綴りにすること（`data/spells.json` の `canonical`）。
  違う綴りを書くと、打ったときに別の呪文が出る。
- **足したら `npm run balance` を回すこと。** 強い呪文を早く渡すと終盤が崩れる。

## 部屋に入った瞬間に始める（`onEnter`）

`onEnter: true` を付けると、その部屋に入った時点で**全ての台詞が続けて流れ**、
閉じると `battleAfter` の戦いに入る。話しかけないと始まらない相手は脇を抜けられるので、
禁書の台の前に立つラスボスのように、通してはいけない相手に使う。


## 呪文を渡す回（`grants` の `talk`）は早い番号にする

`grants` の `talk` は「何回目の会話で渡すか」。**遅い番号に置いてはいけない。**
プレイヤーが何回話しかけるかは、こちらでは決められない。

実際に2つやらかしている。

| 相手 | 置いていた回 | 何が起きるか |
|---|---|---|
| 石壁の彫り込み | 2回目 | 一度しか調べない人は `QOTHREN` を一生手に入れない |
| 司書長 | 5回目 | `SLANE` が無いと**最後の相手に一切ダメージが通らない** |

いまは「その回を**過ぎていれば**渡す」ようにしてある（`i >= g.talk`）ので
取りこぼしは減ったが、それでもその回まで話しかけてもらう必要はある。

- **進行に必要な呪文は `talk: 0` か `1`。**
- 任意の寄り道で拾えるものだけ、後ろに置いてよい。
- 足したら `npm run balance` を回す。ツールは「確実に持っている呪文」しか数えない。
