## 2. 開発専用のシリーズ1資産

- `public/assets/`以下の旧画像・旧BGMは、戦闘と呪文回帰のためだけに残す。
- 旧画像目録は`src/core/assets.ts`、旧曲表は`src/legacy/tracks.ts`が持つ。
- 旧Sceneと旧データは`src/legacy/devRuntime.ts`から動的importした場合だけ読む。
- Viteの本番buildでは`publicDir: false`とし、`public/`全体を`dist/`へコピーしない。
- 通常起動はシリーズ2専用の画像目録とシリーズ2用Track Manifestだけを読む。

## 3. 新規素材を採用するときの規則

1. 完成候補は正本のアート規格と足元寸法を満たすまで本番目録へ入れない。
2. 採用画像は`src/assets/series2/`配下へ置き、`src/core/series2Assets.ts`からだけ参照する。`public/`は本番で配布しないため新素材の置き場にしない。
3. 音は`tracks.ts`へ安定したIDを追加し、PanelDefにはURLでなくIDを書く。
4. 外部由来の素材は作者、取得元、ライセンス、取得日を本台帳または第三者ライセンスへ記す。
5. `npm run build`後に`npm run verify:bundle`を通し、旧作資産とDEV入口の混入がないことを確認する。
6. 生成候補は「未生成→比較待ち→採用／不採用」で管理する。コード描画を完成採用した場合は、生成画像と区別して描画入口と合格した比較を記録する。
7. `docs/assets-license.md`は第一作の記録である。本作の生成元・生成日・加工履歴・利用条件の確認を、前作の記載だけで完了扱いにしない。
